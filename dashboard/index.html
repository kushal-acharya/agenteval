Agent reliability, measured

Right once is not right.

A text-to-SQL agent answering road-safety questions against 37,769 real NHTSA crash records — run five times per question, because the gap between passing and always passing is the number that matters.

What happens under the hood

Every cell in the grid below is one trip through this pipeline. Nothing is mocked — the agent writes its own SQL and runs it against a real 28 MB database.

01
Golden set
Versioned questions with gold SQL, authored by hand.
cases.py
02
Agent
Claude with a run_sql tool. Plans, queries, retries, answers.
adapter.py
03
Runner
Every case × every repeat. Records the full trajectory.
runner.py
04
Execution grader
Runs gold SQL and agent SQL; compares result sets, not query text.
execution.py
05
Metrics
pass@1, pass^k, flakiness, latency, cost.
metrics.py

Every question, every attempt

One row per question, one square per repeat. A row that isn’t uniformly green is a question the agent can answer — but not dependably. Click any row to see the SQL it wrote and why the grader ruled as it did.

Failure taxonomy

A pass rate tells you something is wrong. This tells you what — and it is the part that survives a change of model.
